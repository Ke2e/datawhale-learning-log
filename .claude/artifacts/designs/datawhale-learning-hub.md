- 首门课程直接放在工作区根目录的 `easy-data-x-ai/`，其内聚合个人学习笔记和原课程仓库；原课程仓库保持独立 Git 仓库，仅该子目录排除出学习主库。课程目录及个人笔记仍由主库跟踪，实验按需创建。
- 子目录名称已确认：`note/`（个人笔记）和 `upstream/`（官方材料）。课程入口记录学习目标、上游位置/版本及 Task 索引；忽略规则仅覆盖 `easy-data-x-ai/upstream/`，不覆盖课程入口或笔记。

- Task 笔记按对应文章编号与实际标题分节，保留 Asize 的读后感、原始笔记和已有行动回答；每篇末尾有“课后行动”，列出原文行动要求或建议及来源，留出 Asize 的填写位置。原文未给行动时注明，不伪造必修作业。
- 课后习题由 Asize 自主完成；助手不代答或填写练习结果。后续 Task 按同一结构按需建立，本轮只整理 Task01，不批量创建空白笔记。
- 陪练与验收证据在 Task 笔记内另行标注，原始内容不覆盖；暂不另建验收目录或重复进度表。

### 2. 自学、教学与独立验收

- 本课程目标是产品判断与工程实现并重：能解释方案取舍，也能动手验证关键机制；不默认要求完整产品。
- 默认先由 Asize 阅读材料、记录笔记并尝试作业，再由助手诊断。卡点按需教学，不提前输出完整讲解或答案。
- 两个结果分别记录：课程要求是否满足；是否已有独立掌握证据。允许“课程作业完成，但理解仍需补强”，不混为一个通过状态。

#### 每篇文章怎样测

1. **从原文选重点。** 助手先读 `easy-data-x-ai/upstream/docs/` 的对应文章。测前给 Asize 看一张简表：能力、为什么重要、什么表现能证明会了。每项都标来源：“原文明列”注明目标或课后行动的位置；“助手判断”说明从哪段正文、练习或后续依赖提炼，即便该篇另有明列目标也一样。再按用途区分“必须能独立做”“值得抽查”“用时可查”；这是个人测评安排，不是官方打卡门槛。
2. **用已有证据决定下一问。** 先看 Task 笔记里的原始作答、提示记录和实践结果；笔记写过某个概念不等于能独立运用。一次只问一个问题，等作答再反馈。“事实、决策、反事实”是可选问法，不是每篇三题的配额。一份回答能证明多个目标就分别记下，只追问仍缺证据的部分。
3. **区分独立作答和受助作答。** 概念与判断看能否在新场景独立解释或选择；需要提示时转为教学，同题改对仍属受助，之后换场景或改变关键条件再独立复验。工程能力优先复用学习者已有的课程实践，核对实际操作、关键变更和观察结果；只有口述时保留为待验证。操作时可查官方文档。
4. **按证据收尾。** 逐项说明必测能力：已有独立证据，指向具体作答或实践；待复验，指出原作答中的缺口或得到的提示；未测，只标“未测”，不推断会或不会。只有每个必测点都有独立证据，才提出本篇独立掌握。可以随时暂停，有缺口时留下下次先做的一个动作。

- AC-5 需要提示的验收进入补强，只有不同场景或关键变更的复验结果可成为新的独立掌握证据。

- AC-11 任选一篇文章，可以把原文明列的目标对应到测评简表；即使中途暂停，也能从 Task 笔记分清已有证据、待测或待复验的必测点，无须根据题数推断掌握程度。
